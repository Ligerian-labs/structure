# ADR-0021: Native gRPC through a scoped Effect adapter

- Status: accepted
- Date: 2026-10-06

## Context

Applications need native gRPC interoperability, typed protobuf contracts and all four RPC kinds while retaining Effect cancellation, CQRS policy ownership and the runtime shutdown conventions. HTTP JSON schemas cannot assign protobuf field numbers. Implementing HTTP/2 or protobuf inside Structure would duplicate maintained protocol implementations.

We compared grpc-js with Connect's native gRPC transport. grpc-js has standard binary metadata, trailers, TLS credentials, deadlines, cancellation and all RPC kinds without a native addon. Protobuf-ES v2 generates typed descriptors and codecs without adding a Structure generator. Connect serves as an independent interoperability peer in tests, including Node 22 peers against Structure on Bun in both directions for all four RPC kinds. The dependency cost is grpc-js and its transitive protobuf-loader/map packages plus Protobuf-ES at runtime; Connect and protoc-gen-es are development dependencies only.

An initial unary experiment passed between Bun 1.3.4 and Node 22 peers in both directions. The required blocked-consumer experiment then disproved Bun 1.3 compatibility: with the native client's object buffer full at 16 messages, production grew from 253 to 630 messages on Bun 1.3.14, despite 8 MiB session budgets. The same standalone grpc-js experiment stopped at 17 messages on Node 22, Bun 1.4.0, repository-pinned Bun 1.4.1 and Bun 1.4.2. It contains no Structure or Effect code. The retained reproduction is `packages/grpc/test/fixtures/backpressure.mjs`; the Effect acceptance test also checks that production stops and cancellation cleans up. Bun's [1.4 release](https://bun.sh/blog/bun-v1.4) describes backpressure repairs. Use the existing repository pin, Bun 1.4.1. No runtime change is needed.

We also reproduced an unbound-session-socket exception in grpc-js's disabled-channel-diagnostics server teardown path on Bun. The supported default diagnostics path avoids the access and passes teardown tests. Client IP targets require a DNS TLS server name, since Bun rejects IP addresses in SNI.

## Decision

Use `@grpc/grpc-js` over `node:http2`, with application-owned `.proto` files and descriptors generated by `@bufbuild/protoc-gen-es` v2. Expose typed `service`, `makeServer`, `makeClient`, `Metadata`, `businessFailure` and unary `GrpcCqrs.command/query` adapters. Unary results use Effect; streaming results and request producers use Effect Stream. Callback adaptation stays inside the package.

Keep grpc a leaf over CQRS, observability and runtime. Authentication and policy remain application verification and fiber-context hooks, with no auth/authorization dependency. The bus retains validation, policy and idempotency; the edge forwards verified actor, correlation, key and remaining deadline.

Declared business failures use an explicit protobuf codec for the encoded side of an Effect schema. Their terminal status is FAILED_PRECONDITION, with `structure-failure-version: 1` and up to 8,192 protobuf bytes in `structure-failure-bin`. Standard peers see a normal gRPC error; configured Structure clients schema-decode its typed failure. No arbitrary error serialization or implicit JSON fallback. This also preserves failures after streamed messages. Applications own stable protobuf error field numbers and compatibility.

Use scoped channels/listeners/calls, pull-mode readables and callback-paced writes, a bounded client stream queue, independent bidi send/receive fibers, per-call deadlines and bounded shutdown. Disable every automatic retry policy and stream replay. Security must select TLS or insecure explicitly. Validate framework failure contracts before status mapping, and follow ADR-0020 at the terminal cause boundary: interruption takes precedence, defects cannot hide behind business failures, and only a single declared failure receives its wire codec. Map unexpected failures to fixed safe text and emit bounded telemetry labels without bodies or metadata. Span completion receives only an empty success or fixed status text, never the original cause or response.

## Consequences

The application adds a conventional protobuf generation step and must keep generated artifacts synchronized with source. Stable field numbers allow standard non-TypeScript peers without sharing Effect types. grpc-js owns protocol maintenance; Structure owns interruption and lifecycle adaptation. Scope close and Shutdown stop admission, drain and interrupt overruns; application effects/finalizers must cooperate with interruption.

Bun 1.3.14 cannot meet the required backpressure behavior with this standard transport. The package supports repository-pinned Bun 1.4.1; run the retained reproduction and acceptance tests before changing runtime versions. A separate Node gRPC process would introduce a deployment/IPC boundary and is outside this Bun-native package scope.

grpc-js may discard undelivered native frames on a non-OK status. Structure drains messages already in its readable and response buffers before reporting failure, but applications needing complete delivery across failed calls must define acknowledgement/resume semantics. Session budgets may reject messages before their configured per-message limit. Server channel diagnostics remain enabled as a Bun compatibility constraint. gRPC-Web, reflection, transcoding, custom balancing and a new generator remain outside this adapter. Revisit the transport choice if executable native interoperability, bounded buffering or teardown tests fail on a future supported Bun version, or maintenance ceases.
